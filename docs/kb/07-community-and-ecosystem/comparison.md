# 同类项目对比

> **摘要**：SynthAPI 与其他 API 网关和 LLM 管理平台各有特色。本文档对比 SynthAPI 与 Kong、APISIX、One API、ChatGPT-Next-Web 等项目的差异。

## 与 One API 对比

| 特性 | SynthAPI (new-api) | One API |
|------|-------------------|---------|
| 项目状态 | 活跃维护 | 基本停止维护 |
| UI 设计 | 现代 UI（React 19） | 基础 UI |
| 多语言 | 中/英/法/日/俄/越 | 中/英 |
| 上游提供商 | 40+ | 20+ |
| 订阅系统 | 完整订阅套餐 | 无 |
| 视频生成 | 支持 | 不支持 |
| Responses API | 支持 | 不支持 |
| 智能分组 | 支持 | 不支持 |
| 渠道亲和性 | 支持 | 不支持 |
| 2FA/Passkey | 支持 | 不支持 |
| 自定义 OAuth | 支持 | 不支持 |
| 数据兼容 | 完全兼容 | - |

**总结**：SynthAPI 是 One API 的增强版，在功能、UI、安全性方面都有显著提升。

## 与 Kong 对比

| 特性 | SynthAPI | Kong |
|------|----------|------|
| 定位 | LLM 专用网关 | 通用 API 网关 |
| LLM 支持 | 原生支持 40+ | 需要插件 |
| 计费系统 | 内置 | 需要插件 |
| 用户管理 | 内置 | 需要插件 |
| 部署复杂度 | 简单（单二进制） | 复杂（需要数据库） |
| 性能 | 中等 | 高 |
| 扩展性 | 插件式 | 插件式 |
| 社区 | 中文社区活跃 | 国际社区活跃 |

**总结**：Kong 是通用 API 网关，适合微服务架构；SynthAPI 专注于 LLM 场景，开箱即用。

## 与 APISIX 对比

| 特性 | SynthAPI | APISIX |
|------|----------|--------|
| 定位 | LLM 专用网关 | 通用 API 网关 |
| LLM 支持 | 原生支持 40+ | 需要插件 |
| 计费系统 | 内置 | 无 |
| 性能 | 中等 | 高（基于 NGINX） |
| 部署 | 简单 | 中等 |
| 配置方式 | Web UI + API | YAML + API |
| 社区 | 中文社区 | Apache 社区 |

**总结**：APISIX 性能更高，适合大规模微服务；SynTHAPI 更适合 LLM 场景。

## 与 LiteLLM 对比

| 特性 | SynthAPI | LiteLLM |
|------|----------|---------|
| 语言 | Go | Python |
| 部署方式 | 独立服务 | Python 库/代理 |
| UI | 完整管理后台 | 基础 UI |
| 计费系统 | 完整 | 基础 |
| 用户管理 | 完整 | 基础 |
| 性能 | 高 | 中等 |
| 社区 | 中文社区 | 国际社区 |

**总结**：LiteLLM 更适合作为 Python 库集成到现有应用；SynthAPI 更适合作为独立服务。

## 与 ChatGPT-Next-Web 对比

| 特性 | SynthAPI | ChatGPT-Next-Web |
|------|----------|------------------|
| 定位 | API 网关 | 聊天客户端 |
| API 转发 | 核心功能 | 辅助功能 |
| 用户管理 | 完整 | 无 |
| 计费系统 | 完整 | 无 |
| 渠道管理 | 完整 | 基础 |
| 多模型支持 | 40+ 提供商 | OpenAI 兼容 |
| 部署 | 服务端 | 前端 |

**总结**：ChatGPT-Next-Web 是前端聊天应用；SynthAPI 是后端 API 网关。两者可以配合使用。

## 与 FastGPT 对比

| 特性 | SynthAPI | FastGPT |
|------|----------|---------|
| 定位 | API 网关 | AI 应用平台 |
| 知识库 | 无 | 内置 |
| 工作流 | 无 | 内置 |
| API 转发 | 核心功能 | 辅助功能 |
| 用户管理 | 完整 | 完整 |
| 计费系统 | 完整 | 完整 |

**总结**：FastGPT 是 AI 应用开发平台；SynthAPI 是 API 网关。可以配合使用。

## 选型建议

### 选择 SynthAPI

- 需要统一管理多个 AI API
- 需要完整的计费系统
- 需要用户管理和权限控制
- 需要中文文档和支持
- 需要简单易用的管理后台

### 选择 Kong/APISIX

- 需要通用 API 网关
- 需要高性能
- 已有 NGINX 基础设施
- 需要丰富的插件生态

### 选择 LiteLLM

- 使用 Python 技术栈
- 需要作为库集成
- 不需要复杂管理功能

### 选择 ChatGPT-Next-Web

- 只需要聊天前端
- 不需要计费功能
- 个人使用
